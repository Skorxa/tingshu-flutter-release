# 陷阱清单

按踩坑频率排序。前四类几乎每次写源都会遇到。

## 一、引擎与协议

1. **状态码要自己判**：引擎对任何状态码都走 `success`，4xx/5xx 不会抛异常。必须 `r.statusCode === 200 ? ... : reject(new Error('HTTP '+r.statusCode))`。
2. **`res.data` 类型不定**：能 JSON.parse 就是对象/数组，否则是原始字符串。非标准 JSON（单引号 dict、Python 风格 `None`/`True`）用 `new Function('return(' + d + ')')()` 兜底，再失败才报错。
3. **无结果 ≠ 出错**：搜不到返回空 `list`，不要 throw。
4. **`hasMore`/`isFinished` 只认严格 `true`**，`1`、`'true'` 都当 false。
5. **chapterId / bookId 必须能二次识别**：无法二次请求时，用 `encodeURIComponent(JSON.stringify({...}))` 把定位信息和元数据一起塞进去（`_pack`/`_unpack` 写法见 `tj-juhe.js`）。
6. **不要用浏览器 API**：`document`、`DOMParser`、`fetch`、`localStorage` 一律没有；HTML 用正则。
7. **单次方法调用 30 秒超时**：大书目录要在源内并发拉取 + 缓存，别让一次调用超时。

## 二、目录顺序（用户明确要求逐平台核对）

**统一做法**：不信任服务端顺序 —— 一次拉全量 → 排序 → 沉底干扰项 → 内存分页。

| 平台 | 服务端顺序 | 处理 |
|---|---|---|
| 酷我专辑 | **最新在前（倒序）** | `list.reverse()` |
| 酷我歌单 | 歌单既定顺序 | 保持 |
| 网易大歌单 | `/playlist/detail` 的 `tracks` **被截断**（只回 10 条） | 改用 `playlist.trackIds` 全量 + 分批 `/api/song/detail?ids=[…]`（每批 100） |
| QQ 专辑 | **服务端乱序**，`index_cd` 全 0 | 从章节名提取首个数字做数值排序 |
| 酷狗专辑 | 分页顺序正常 | 保持 |
| 懒人听书 | 顺序正常 | 保持 |
| 喜马拉雅 | 顺序正常（`isAsc=true`） | 保持 |

排序辅助函数（`tj-juhe.js` 里已有可直接抄）：

- `_sortByChapterNo(list)`：从名称提取首个 2–5 位数字，若 ≥50% 条目能提取到数字则按数字排序，无数字的追加末尾
- `_sinkNoChapterNo(list)`：稳定分区，把「片花 / 预告 / 无集数」等无数字条目沉到末尾

**验收方式**：抽首集、次集、末集三者核对（例：kw 应为首集「山边小村」，tx 应从 `0001` 递增到 `大结局`）。别只看总数对不对。

## 三、请求与接口

1. **ID 参数可能类型敏感**：传数字报「参数无效/分类参数无效」时改传字符串（喜马拉雅 `album_id` 就是这种）。
2. **响应可能是两层信封**：`{code,msg,data:{url}}`；也可能裸对象 `{url}`。写 `const d = env.data || env` 两种都兼容。
3. **接口可能在多个 CDN 后端间轮换**：实测同一接口连续 5 次返回了 2 个不同后端，其中一个是失效域名（全 403）。源里检测已知坏域名并重试换取新后端。
4. **需要会话的接口**：无 Cookie 常返回 `{"error":"非法访问"}` 或首页内容 —— 先请求首页建会话；Referer 用首页通常就够。
5. **移动端接口的伪装头**：很多平台要求 App 版 UA **并且**带设备 Cookie（如喜马拉雅 `ting_6.6.99(...)` + `1&_device=android&<uuid>&…`），缺一个就返回「内容已下架」（其实是风控）。
6. **防盗链**：音频/封面 `/180x254` 之类的处理后缀可去掉；图片和音频返回 `{ url, headers }` 带上 Referer。
7. **优先 https**：http 容易被风控，返回时 `url.replace(/^http:/, 'https:')` 试试（不行再退回 http）。
8. **做限速**：源内 `_gate()` 串行队列（间隔 100–300ms）避免被风控封 IP。

## 四、已下架/受限内容要区分

- 专辑已下架：目录接口报错（如 `924 亲，该内容因故已下架`）→ 提示「该专辑已下架」，不是源坏了
- 会员/付费章节：目录正常但音频为空 → 提示具体原因，或转兜底通道
- 搜索能搜到但打开失败：搜索命中了下架专辑，换一本验证源是否正常

## 五、工具链（写源过程本身）

1. **PowerShell 脚本不要含中文**：脚本文件按 UTF-8 写、shell 按 GBK 读 → 中文变乱码并导致语法错误。脚本内容保持纯 ASCII。
2. **`pwsh -File` 与 `& script.ps1` 不同**：后者是 Windows PowerShell 5.1，`Invoke-WebRequest` 会因非交互模式报错。**一律用 `curl.exe`**（配合 `-b/-c` cookie 罐文件）。
3. **不要给变量起自动变量名**：`$home`、`$host` 等在 PowerShell 里是只读自动变量，赋值会失败（大小写不敏感）。
4. **`??` 空合并运算符在旧 PowerShell 不支持**。
5. **curl 输出吃进变量**：用 `-o 文件` 再读文件，直接把响应体赋给变量会被拆成行数组。
6. **JSON 请求体用文件**：`curl.exe --data-binary "@file.json"`，避免 shell 引号和编码破坏；含中文的 body 一定走文件。
7. **JS 代码不要走命令行传参**：引号会被 shell 吃掉，写成 `.js` 文件再读。

## 六、发布相关

- 源 `id` 全局唯一，**重复会覆盖旧源**：改造已有源时沿用原 id，新增站点用新 id
- 清单里的 `version` 是**清单整体版本号**，客户端靠它判断是否有更新；改了任何源都必须 +1
- 删除源时既要移除清单条目，也要删 R2 上的文件，否则会有孤儿文件
- 上传后可用 `https://jt.966001.xyz/health` 验证服务，订阅数据需设备授权（匿名访问 401 属正常）
