# 听书音源编写规范

> 适用于「橘听」App。音源是一段在内置 QuickJS 引擎中运行的 JavaScript 脚本，负责把某个网站/接口的有声书数据，转换成 App 能识别的统一结构。
>
> 本规范基于引擎实现（`lib/source/js_engine.dart`、`assets/js/uni_shim.js`、`lib/source/source_manager.dart`、`lib/source/models.dart`）整理，所有字段与行为均与代码一致。

## 1. 运行机制

- 引擎是内嵌的 **QuickJS**(通过 `flutter_js`),不是浏览器,**没有 DOM、`window`、`fetch`、`XMLHttpRequest`、`localStorage`**。
- 引擎注入了一个全局 `uni` 对象(见 [第 5 节](#5-运行时-api-uni)),网络请求只能通过 `uni.request` 发起,由 Dart 侧的 `dio` 实际执行。
- 引擎自带:`console`、`setTimeout`、`JSON`、`Promise`,以及现代 JS 语法(`async/await`、箭头函数、模板字符串、可选链 `?.`、解构等)。
- 加载方式:你的脚本会被这样执行 ——
  ```js
  new Function('uni', 'return (\n' + 你的代码 + '\n)')(uni)
  ```
  因此**整段脚本必须是一个「对象表达式」**,用一对圆括号包起来:`({ ... })`。返回值必须是带 `id` 的对象,否则报错「音源缺少 id」。

## 2. 音源骨架

```js
({
  id: 'my-source',        // 必需：全局唯一标识。重复会覆盖同 id 的旧音源
  name: '我的音源',        // 显示名称。缺省时回退用 id
  apiVersion: 1,          // 可选：当前协议版本，缺省按 1 处理

  // 可选：声明后，音源管理页长按该源会显示“登录”
  login: {
    url: 'https://example.com/login',
    configKey: 'cookie'
  },

  // 可选：声明后，音源管理页会显示“设置/音源配置”
  configFields: [
    { key: 'cookie', label: 'Cookie', type: 'textarea', required: true }
  ],

  // 三个必需方法，可以是 async，也可以返回 Promise
  search(keyword, page, pageSize) { /* ... */ },
  getChapters(bookId, page, pageSize) { /* ... */ },
  getAudioUrl(chapterId) { /* ... */ },

  // 可选：发现页内容（实现了才会在「发现」tab 显示该音源）
  discover() { /* ... */ },

  // 可选：自定义辅助方法/字段，方法内用 this 访问
  _req(params) { /* ... */ },
})
```

要点:

- `id` **必需且唯一**;`name` 建议填写。
- `login` 和 `configFields` 决定 App 是否显示登录/设置入口。没有声明的源不会无故出现这些菜单。
- `search` / `getChapters` / `getAudioUrl` 三个方法**必需**；`discover` **可选**，实现了才会出现在「发现」页（见 [第 3.1 节](#31-可选方法discover)）。
- 方法内的 `this` 指向音源对象本身，可放公共逻辑（如上面的 `this._req(...)`）。
- 方法可同步返回、可 `async`、可返回 `Promise`，引擎统一 `await`。
- 单次方法调用超时为 **30 秒**(引擎层),超时会报「音源调用超时」。

## 3. 三个必需方法

| 方法 | 调用参数 | 默认值 | 返回 |
|---|---|---|---|
| `search(keyword, page, pageSize)` | 关键词、页码(从 1 起)、每页数量 | `pageSize=20` | [搜索结果](#41-search-的返回) |
| `getChapters(bookId, page, pageSize)` | 书 id、页码(从 1 起)、每页数量 | `pageSize=100` | [目录结果](#42-getchapters-的返回) |
| `getAudioUrl(chapterId)` | 章节 id | — | [音频结果](#43-getaudiourl-的返回) |

- `bookId` 来自 `search` 返回的 `list[].bookId`;`chapterId` 来自 `getChapters` 返回的 `list[].chapterId`。要保证它们能被你自己的接口再次识别(原样回传即可)。
- 页码 **从 1 开始**。若目标接口从 0 开始(如酷我),请在方法内 `page - 1` 转换。
- 失败时**抛出 `Error`**(`throw new Error('原因')`),错误信息会显示在界面和运行日志里。**不要**默默返回空对象。
- 「没有结果」与「出错」是两回事:无结果应返回**空列表** `{ list: [], ... }`,不要抛错。

### 3.1 可选方法 `discover`

```js
discover() { /* ... */ }
```

- **无参数**。App 调用时一次性拉取该音源的首页/分类/榜单内容，**不做分页**。
- 返回 [发现页结果](#44-discover-的返回)：`{ sections: [{ title, list: [Book] }] }`。
- **可选**：不实现不会报错，该音源只是不会出现在「发现」tab。App 在加载音源时通过 `typeof src.discover === 'function'` 检测是否支持。
- 失败时同样 `throw new Error(...)`；空内容返回 `{ sections: [] }` 而非抛错。
- 实现建议：`sections` 每段对应一个分类/榜单（如「热门」「玄幻」「新品」），每段 `list` 取 6–10 本即可，过多会拖慢首屏。

## 4. 返回数据结构

字段类型由 Dom 端 `models.dart` 解析,遵守以下约定:
- 字符串字段缺省转为 `''`;`id` 类字段即使是数字也会被转成字符串,可放心。
- `page` / `maxPage` / `index` / `trackCount` 取整数,缺省为对应默认值。
- `hasMore` / `isFinished` **只有严格等于 `true` 才生效**,其他值(包括 `1`、`'true'`)都按 `false`。

### 4.1 `search` 的返回

```js
{
  list: [
    {
      bookId: 'string',   // 必需,后续传给 getChapters
      title:  'string',
      cover:  'string',   // 封面图 URL(也用于动态主题取色)
      author: 'string',
      intro:  'string',
    },
    // ...
  ],
  page:    1,             // 当前页
  maxPage: 1,             // 总页数
  hasMore: true,          // 是否还有下一页(true/false)
}
```

> App 会聚合搜索所有已开启音源,因此请确保翻页字段(`page` / `maxPage` / `hasMore`)正确,否则「上拉加载更多」会异常。

### 4.2 `getChapters` 的返回

```js
{
  info: {
    title:      'string',
    cover:      'string',
    author:     'string',
    trackCount: 0,         // 总集数(整数)
    isFinished: false,     // 是否完结(true/false)
  },
  list: [
    {
      chapterId: 'string', // 必需,后续传给 getAudioUrl
      index:     1,         // 集号(整数),建议全书连续
      name:      'string',  // 章节名
    },
    // ...
  ],
  page:    1,
  maxPage: 1,
  hasMore: true,
}
```

> `index` 建议按全书连续编号(分页时用 `offset = (page-1)*pageSize` 累加),界面会原样展示。

### 4.3 `getAudioUrl` 的返回

两种形式任选:

```js
// 形式一:直接返回可播放的 URL 字符串
return 'https://example.com/audio/123.m3u8'

// 形式二:URL + 自定义请求头(用于过防盗链 Referer / UA 等)
return {
  url: 'https://example.com/audio/123.mp3',
  headers: { 'Referer': 'https://example.com', 'User-Agent': 'okhttp/4.9.2' },
}
```

- 必须返回 `http`/`https` 开头的可直接播放地址(支持 mp3 / m4a / flac / m3u8 等 `just_audio` 能播的格式)。
- 解析不到时抛错:`throw new Error('该章节暂无音频')`。
- `headers` 会在**播放和缓存下载**时一并带上。

### 4.4 `discover` 的返回

```js
{
  sections: [
    {
      title: '热门',              // 段标题，App 会显示为「音源名 · 热门」
      list: [
        {
          bookId: 'string',       // 必需，与 search 的 bookId 同源，点击会进目录
          title:  'string',
          cover:  'string',
          author: 'string',
          intro:  'string',
        },
        // ... 每段建议 6–10 本
      ],
    },
    // ... 可多段（热门 / 分类 / 新品 等）
  ],
}
```

- `sections` **必需为数组**；缺省时 App 报「discover 返回缺少 sections 数组」。
- 每段的 `list` **必需为数组**；段内 `list` 为空时该段不显示。
- `Book` 字段与 [4.1 search](#41-search-的返回) 完全一致：`bookId` / `title` 必需，其余可空。
- `title` 可空，为空时 App 用音源名作为段标题。
- 不做分页，一次性返回全部段。段数与每段本数都不宜过多，避免首屏过慢。

## 5. 运行时 API(`uni.*`)

引擎只提供以下能力(见 `assets/js/uni_shim.js`):

### `uni.request(options)`

发起网络请求,通过回调返回。**推荐用 `Promise` 包装**后配合 `async/await`。

```js
uni.request({
  url: 'https://...',          // 必需
  method: 'GET',               // 默认 'GET',大小写不敏感
  data: { k: 'v' },            // GET 时作为查询参数;其他方法作为请求体
  header: { 'User-Agent': '...' }, // 自定义请求头
  timeout: 15000,              // 毫秒,默认 15000
  success: (res) => {          // res = { statusCode, data }
    // res.statusCode: HTTP 状态码(数字)
    // res.data: 见第 6 节(可能是已解析对象,也可能是原始字符串)
  },
  fail: (err) => {             // err = { errMsg }
    // 仅网络层错误(超时、连接失败)才触发;HTTP 4xx/5xx 不算 fail
  },
})
```

### `uni.getStorageSync(key)` / `uni.setStorageSync(key, value)`

读取配置和临时键值：

- `configFields` 声明的字段会持久化到 App 本地，并注入到 `this.config`。
- `uni.getStorageSync('sourceConfig')` 会返回当前音源已注入的配置对象。
- `uni.getStorageSync('cookie')`、`uni.getStorageSync('token')` 等常见键会从当前音源配置里读取。
- 音源自己通过 `uni.setStorageSync(key, value)` 写入的值只存在于当前 JS 运行环境，App 重启后可能丢失。不要用它保存长期 Token。

优先读取 `this.config`，只在兼容旧源时使用 `uni.getStorageSync(...)`。

### `uni.crypto.aesCbcDecrypt(options)`

通过 Dart 侧 PointyCastle 执行 AES/CBC/PKCS7 解密，返回 `Promise<string>`：

```js
const plainText = await uni.crypto.aesCbcDecrypt({
  cipherText: encryptedBase64,
  key: keyText,
  iv: ivText,
  inputEncoding: 'base64',
  keyEncoding: 'utf8',
  ivEncoding: 'utf8'
})
```

- `cipherText`、`key`、`iv` 必需。
- 编码支持 `base64`、`hex`、`utf8`（`text` 等同于 `utf8`）。
- AES key 解码后必须是 16、24 或 32 字节，IV 必须是 16 字节。
- 当前固定使用 CBC 模式和 PKCS7 padding，适合迁移 Legado 中依赖 Java AES/CBC 的规则。

## 6. 网络请求要点

这些是音源最容易踩的点,务必理解:

1. **响应体自动解析**:Dart 侧先把响应当原始字符串取回,再尝试 `JSON.parse`。
   - 能解析成 JSON → `res.data` 是**对象/数组**;
   - 不能解析 → `res.data` 是**原始字符串**。
   - 因此对非标准 JSON(如返回 Python 单引号 dict、JSONP 包裹)要自己处理字符串,例如:
     ```js
     let d = res.data
     if (typeof d === 'string') {
       try { d = JSON.parse(d) } catch (e) { /* 再尝试其他方式 */ }
     }
     ```

2. **状态码要自己判断**:引擎设置了「任何状态码都不抛异常」,所以 4xx/5xx 也会进 `success`。务必检查:
   ```js
   success: r => r.statusCode === 200 ? resolve(r.data) : reject(new Error('HTTP ' + r.statusCode))
   ```

3. **GET 的 `data` 是查询参数**,非 GET 的 `data` 是请求体。需要复杂 query 时也可自己拼到 `url` 上。

4. **明文 HTTP**:本 App 已开启 `usesCleartextTraffic`,`http://` 接口可用。但很多站点对 `http` 有风控或要求 `https`,**优先使用 `https`**。

5. **自动重定向**已开启(`followRedirects: true`)。

6. **防盗链**:音频/封面若校验来源,在 `getAudioUrl` 用 `{ url, headers }` 返回带 `Referer`/`User-Agent` 的头。

## 7. 登录与配置

需要登录的音源必须由音源自己声明登录能力。App 只负责提供统一入口、内置 WebView 和配置注入；具体 Cookie、Token、接口参数仍由 JS 音源自己使用。

### 7.0 入口显示规则

App 不会给所有音源都显示登录和设置：

- 声明 `login: { url, configKey }` 或 `loginUrl` 后，**设置 → 音源管理 → 长按该音源** 才会显示“登录”。
- 声明 `configFields`，或声明了可推断的 `login.configKey` 后，音源管理页才会显示“设置”，搜索结果/书架长按才会显示“音源配置”。
- 搜索结果或书架书籍长按始终可用“调试音源”，用于跑通搜索、目录、音频解析并写入运行日志。
- 青天聚合类旧源会被 App 额外兼容：`id` 以 `qt-` 开头，或代码中包含 `qt_cookie` / `gyks.cf` 时，会自动推断登录页和 `qt_cookie` 配置字段。

新源建议显式声明能力，不要依赖推断。这样源文件自己就能说明它需要登录、需要哪些配置，也方便以后迁移。

### 7.1 手动配置字段

如果用户需要手动粘贴 Cookie、Token、账号等字段，声明 `configFields`：

```js
({
  id: 'vip-source',
  name: '需要登录的音源',

  configFields: [
    {
      key: 'cookie',
      label: 'Cookie',
      type: 'textarea',
      hint: '从网页或抓包工具复制 Cookie',
      required: true
    },
    {
      key: 'userAgent',
      label: 'User-Agent',
      type: 'text',
      hint: '可选'
    }
  ],

  _cookie() {
    return (this.config && this.config.cookie) || ''
  },
})
```

配置字段类型：

| type | 用途 |
|---|---|
| `text` | 普通单行文本 |
| `password` / `token` | 单行隐藏输入，适合 Token、密码 |
| `textarea` | 多行文本，适合 Cookie |
| `json` | JSON 配置对象，保存时会解析成对象 |

App 会把用户保存的字段注入到 `this.config`：

```js
const cfg = this.config || {}
const cookie = cfg.cookie || ''
const token = cfg.token || ''
```

也兼容：

```js
const cfg = uni.getStorageSync('sourceConfig') || {}
const cookie = uni.getStorageSync('cookie')
const token = uni.getStorageSync('token')
```

### 7.2 内置 WebView 登录

如果站点有登录页，推荐声明 `login`。用户在“设置 → 音源管理”长按该音源，点“登录”，App 会用内置 WebView 打开登录页。用户登录完成后点右上角“完成”，App 会读取 WebView Cookie 并保存到 `login.configKey` 指定的配置字段。

```js
({
  id: 'vip-source',
  name: '需要网页登录的音源',

  login: {
    url: 'https://example.com/login',
    configKey: 'cookie'
  },

  configFields: [
    {
      key: 'cookie',
      label: 'Cookie',
      type: 'textarea',
      hint: '内置登录页会自动写入；也可以手动粘贴',
      required: true
    }
  ],

  _cookie() {
    return (this.config && this.config.cookie) || ''
  },
})
```

也支持简写：

```js
loginUrl: 'https://example.com/login'
```

简写只声明登录页；如果要自动保存 Cookie，仍建议使用完整 `login: { url, configKey }`。

### 7.3 青天聚合类源示例

青天源通常共用接口 `https://v1.gyks.cf`，登录页是 `https://v1.gyks.cf/login`，Cookie 键名建议统一用 `qt_cookie`。

```js
({
  id: 'qt-kuwo',
  name: '青天·酷我',
  _base: 'https://v1.gyks.cf',
  _sub: 'svip_酷我',

  login: {
    url: 'https://v1.gyks.cf/login',
    configKey: 'qt_cookie'
  },

  configFields: [
    {
      key: 'qt_cookie',
      label: '青天 Cookie',
      type: 'textarea',
      hint: '内置登录页会自动写入；也可以手动粘贴',
      required: true
    }
  ],

  _cookie() {
    return uni.getStorageSync('qt_cookie') || ''
  },

  _get(path, params = {}) {
    const ck = this._cookie()
    const qs = Object.entries(params)
      .map(([k, v]) => k + '=' + encodeURIComponent(v))
      .join('&')
    const url = this._base + path + (qs ? '?' + qs : '')
    const header = { 'User-Agent': 'okhttp/4.9.2' }
    if (ck) header.Cookie = ck
    return new Promise((resolve, reject) => {
      uni.request({
        url,
        method: 'GET',
        header,
        timeout: 15000,
        success: r => r.statusCode === 200
          ? resolve(r.data)
          : reject(new Error('HTTP ' + r.statusCode)),
        fail: e => reject(new Error(e.errMsg || '网络失败'))
      })
    })
  },
})
```

App 额外兼容青天旧源：

- 源 `id` 以 `qt-` 开头，或代码里包含 `qt_cookie` / `gyks.cf`，App 会自动推断登录页为 `https://v1.gyks.cf/login`。
- `uni.getStorageSync('qt_cookie')` 会读取 `this.config.qt_cookie`，没有时回退到 `this.config.cookie`。

建议新源仍然显式声明 `login` 和 `configFields`，可读性更好，也方便以后迁移。

## 8. 完整示例(带注释)

以内置「元气听书」为模板,这是一个干净、可直接套用的最小实现:

```js
// 元气听书(单接口,GET + 查询参数,标准 JSON,无鉴权)
({
  name: '元气听书',
  id: 'yuanqi',

  // 公共请求:封装成 Promise,统一判状态码
  _req(data) {
    return new Promise((resolve, reject) => {
      uni.request({
        url: 'https://music.haitangw.cc/tingshu/tingshu.php',
        data,                                   // GET → 作为查询参数
        header: { 'User-Agent': 'okhttp/4.9.2' },
        timeout: 15000,
        success: r => r.statusCode === 200
          ? resolve(r.data)                     // r.data 已是解析好的对象
          : reject(new Error('HTTP ' + r.statusCode)),
        fail: e => reject(new Error(e.errMsg || '网络失败')),
      })
    })
  },

  async search(keyword, page = 1, pageSize = 20) {
    const res = await this._req({ name: keyword, page, pageSize })
    const rows = Array.isArray(res.data) ? res.data : []
    return {
      list: rows.map(item => ({
        bookId: item.itemId,
        title:  item.title    || '',
        cover:  item.cover    || '',
        author: item.nickname || '',
        intro:  item.intro    || '',
      })),
      page: res.page || page,
      maxPage: res.maxPage || 1,
      hasMore: !!res.hasMore,
    }
  },

  async getChapters(bookId, page = 1, pageSize = 100) {
    const res = await this._req({ itemId: bookId, page, pageSize })
    const rows = Array.isArray(res.data) ? res.data : []
    const offset = (page - 1) * pageSize        // 全书连续集号
    return {
      info: {
        title: res.itemTitle || '',
        cover: res.cover || '',
        author: res.nickname || '',
        trackCount: res.trackCount || res.total || 0,
        isFinished: !!res.isFinished,
      },
      list: rows.map((item, i) => ({
        chapterId: item.playId,
        index: offset + i + 1,
        name: item.title || '',
      })),
      page: res.page || page,
      maxPage: res.maxPage || 1,
      hasMore: !!res.hasMore,
    }
  },

  async getAudioUrl(chapterId) {
    const res = await this._req({ playId: chapterId })
    if (res.msg === 'success' && res.url) return res.url
    throw new Error('该章节暂无音频（VIP 或未更新）')
  },
})
```

### 8.1 加上「发现页」(`discover`)

在任意已有音源上追加一个 `discover` 方法，该音源就会出现在「发现」tab。下面以复用上面的 `_req` 为例，拉取站点首页/榜单并按段返回：

```js
({
  name: '元气听书',
  id: 'yuanqi',

  _req(data) { /* 同上，省略 */ },

  async search(keyword, page = 1, pageSize = 20) { /* 同上 */ },
  async getChapters(bookId, page = 1, pageSize = 100) { /* 同上 */ },
  async getAudioUrl(chapterId) { /* 同上 */ },

  // 发现页：多段内容，每段一个分类/榜单
  async discover() {
    // 假设接口提供首页推荐 + 各分类榜单，分别请求
    const [hot, fantasy, city] = await Promise.all([
      this._req({ type: 'hot', page: 1, pageSize: 8 }),
      this._req({ type: 'fantasy', page: 1, pageSize: 8 }),
      this._req({ type: 'city', page: 1, pageSize: 8 }),
    ])
    const toBooks = res =>
      (Array.isArray(res.data) ? res.data : []).map(item => ({
        bookId: item.itemId,
        title:  item.title    || '',
        cover:  item.cover    || '',
        author: item.nickname || '',
        intro:  item.intro    || '',
      }))
    return {
      sections: [
        { title: '热门',   list: toBooks(hot) },
        { title: '玄幻',   list: toBooks(fantasy) },
        { title: '都市',   list: toBooks(city) },
      ],
    }
  },
})
```

要点：

- `discover` 无参数，一次性返回所有段，**不分页**。
- 每段 `list` 复用 `search` 里同款的 `Book` 映射即可，字段口径完全一致。
- 段数建议 2–5 段，每段 6–10 本；过多会拖慢首屏。
- 也可以只返回单段 `{ sections: [{ title: '推荐', list: [...] }] }`，App 同样能展示。

## 9. 调试与排错

### 一键调试音源

搜索结果或书架里的书籍可以长按，选择 **调试音源**。App 会按当前书籍自动跑一遍：

1. `search(keyword, page, pageSize)`：确认搜索是否能返回目标书。
2. `getChapters(bookId, page, pageSize)`：确认目录是否能解析，日志会打印页码、章节数和前几集。
3. `getAudioUrl(chapterId)`：取第一集音频地址，确认播放 URL 和请求头是否有效。

调试结果会写入 **设置 → 诊断 → 查看运行日志**。这相当于一次自动化的“搜索 → 获取目录 → 获取音频”链路检查，适合排查新源、登录源、字段变更和风控问题。

### 看运行日志(最重要)

设置 → 诊断 → **查看运行日志**。搜索/播放/缓存/音源的每一步都有记录:
- `音源搜索完成`:含「新增结果」数量。**结果为 0 且无报错 = 接口正常但没数据**(关键词无匹配、接口风控返回空、字段名对不上)。
- `音源搜索失败`:含 `Error` 的具体信息。

> 让报错「会说话」:在 `throw new Error(...)` 里带上诊断信息。例如目录解析不到时:
> ```js
> if (tracks.length === 0) {
>   throw new Error('字段:' + Object.keys(res).join(',') + ' | ' + JSON.stringify(res).slice(0, 300))
> }
> ```
> 这样日志里就能直接看到接口实际返回了什么。

`console.log(...)` 的输出在开发时(`flutter run` 的控制台)可见,但**不会**进入 App 内的运行日志;面向用户的诊断请用 `throw new Error`。

### 常见错误对照

| 现象 / 报错 | 原因 | 处理 |
|---|---|---|
| 音源缺少 id | 脚本不是 `({...})` 对象,或没写 `id` | 检查最外层是否被 `({ })` 包裹、是否有 `id` |
| 音源解析失败 | JS 语法错误 | 检查括号/逗号,确认未用浏览器专属 API |
| 音源无方法: search | 方法名拼错或没实现 | 三个方法名必须精确匹配 |
| HTTP 4xx/5xx | 接口要求鉴权/参数/UA | 补 `header`、核对参数;改用 `https` |
| 音源调用超时 | 接口太慢或卡死 | 优化请求;确认接口可达 |
| 搜到 0 条但不报错 | 接口返回空 / 字段名不符 | 见下方「搜不到」清单 |

### 「搜不到」排查清单

1. 音源是否**已开启**(设置 → 音源管理)。
2. 看运行日志该音源是「失败」还是「完成但结果 0」。
3. 「完成但结果 0」→ 八成是接口返回结构变了:在 `search` 里把 `res` 打进 `throw` 看真实字段(临时调试),核对你取的字段路径(如 `res.data.data`)是否正确。
4. 用浏览器/`curl` 直接请求该接口,确认它现在还通、还按老结构返回。
5. 目标站是否有**风控**(需要特定 UA、签名、Cookie、或封了 `http`)。
6. 换个一定有结果的关键词测试,排除「确实没这本书」。

> 例:内置「北极听书」(酷我代理)搜索常返回 0 条 —— App 已允许明文 `http`,所以不是 App 的问题,而是酷我接口参数/风控变化导致返回空。可按上面第 3、4 步,用 `throw` 打印 `search` 的真实返回来定位。

## 10. 导入音源

设置 → 音源管理:

- **本地导入**：调起系统文件管理器，选择 `.js`、`.txt` 等纯文本音源文件。
- **粘贴导入**：点右上角粘贴按钮，手动粘贴整段 `({ ... })` 脚本。
- **链接导入**：填写一个返回纯文本脚本内容的 URL（`https` 优先）。

导入后会立即在 QuickJS 中编译注册；`id` 重复会覆盖旧音源。可在列表里开启/关闭、设为当前、删除。

长按某个音源会打开管理菜单：

- **登录**：只有源声明了 `login` / `loginUrl`，或被 App 推断为青天聚合类源时显示。
- **设置**：只有源声明了 `configFields`，或有可推断的登录配置键时显示。
- **开启/关闭**、**设为当前音源**、**删除**：所有音源通用。

## 11. 编写检查清单

提交音源前逐项确认:

- [ ] 最外层是 `({ ... })`,有唯一 `id` 和 `name`。
- [ ] 实现了 `search`、`getChapters`、`getAudioUrl` 三个方法,方法名精确。
- [ ] 返回结构字段与[第 4 节](#4-返回数据结构)完全一致(尤其 `list`、`bookId`、`chapterId`)。
- [ ] 页码按从 1 起处理;`index` 全书连续。
- [ ] 每次请求都判断 `statusCode`;失败 `throw new Error`,无结果返回空 `list`。
- [ ] 接口尽量用 `https`;音频防盗链用 `{ url, headers }`。
- [ ] 需要 Cookie、Token 或账号参数的源已声明 `configFields`，并在请求头或接口参数里实际使用这些字段。
- [ ] 需要网页登录的源已声明 `login: { url, configKey }`，且 `configKey` 对应一个可查看/清空的配置字段。
- [ ] 若实现了 `discover`，返回 `{ sections: [{ title, list: [Book] }] }`，`bookId` 与 `search` 同源；段数与每段本数适量（建议每段 6–10 本）。
- [ ] 已在真机/模拟器跑通「搜索 → 进目录 → 播放」整链路,并在运行日志确认无异常。
